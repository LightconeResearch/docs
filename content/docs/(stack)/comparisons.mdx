Lightcone combines an ASTRA research record with execution and reporting tools. The comparisons
below focus on that choice of record and workflow. External product details were checked against
the linked sources in September 2026.

## Claude Science

[Claude Science](https://www.anthropic.com/news/claude-science-ai-workbench) brings literature tools,
code execution, scientific viewers and compute access into one application. Anthropic describes
artifact histories containing code, environment and conversation context, plus a reviewer agent
that checks citations and calculations. It also supports forking sessions to compare approaches.

Lightcone records the analysis in `astra.yaml` and stores source history and result provenance in
git and git-annex. Methodological alternatives are named decision options, and universe files
select which configurations to run. Those files can be read independently of the agent or viewer.

| If you need… | Relevant distinction |
| --- | --- |
| Integrated scientific viewers and connectors | Claude Science supplies a broad application environment, with a strong life-sciences focus. |
| A declared record of methods and alternatives | ASTRA gives those choices explicit fields that Lightcone's runner and reports share. |
| An agent to help with a Lightcone project | The Lightcone plugins support Claude Code and Codex. This does not imply an integration with the Claude Science app. |

Both approaches keep records that help with review. Neither an execution history nor a matching
citation establishes that a scientific conclusion is correct.

## Workflow and data tools

[Snakemake](https://snakemake.readthedocs.io/en/stable/) and
[Nextflow](https://www.nextflow.io/docs/latest/overview.html) describe and execute pipelines across
computing environments. [DVC](https://dvc.org/doc/command-reference/) adds data versioning and
pipeline reproduction to a git workflow.

The Lightcone CLI also resolves dependencies, reuses outputs and records runs. Its input format,
ASTRA, additionally records methodological options, prior insights and findings. That may be useful
when you want to review how choices affect a conclusion alongside the execution details.

Check the requirements of your workload before moving an existing pipeline: `lc` currently
executes flat analyses, and each recipe must fit on one worker. See
[execution limits](/lightcone-cli/cluster#execution-requirements-and-limits).

## Notebooks

Notebooks are useful for exploration and for keeping code, output and explanation together.
A reproducible notebook still needs its execution order, inputs and environment to be recorded.

[Lightcone Lab](/lightcone-lab) adds an ASTRA inventory and pipeline to JupyterLab. You can continue
exploring in notebooks and move steps that need recorded outputs into CLI recipes.

## Research agents

Research systems such as [Kosmos](https://advances.edisonscientific.com/research/how-we-built-kosmos/)
coordinate long-running analysis and hypothesis testing. Their autonomy and collaboration features
vary by system and release.

Lightcone's [agent workflow](/agent-skills/lightcone) starts by reviewing a specification with you
and uses the CLI to generate results. The stack supplies a way to record and execute the analysis;
you remain responsible for its question, methods and interpretation.
