You need two things on your machine, [uv](https://docs.astral.sh/uv/) and git, plus a coding agent:
Claude Code or Codex. uv can install Python and the CLI's dependencies. Report previews and
JupyterLab have additional requirements, linked below.

<Callout title="Supported platforms">
  Linux (glibc 2.34 or newer, x86_64 or aarch64) and macOS (14 or newer on Apple silicon, 15 or newer
  on Intel). On Windows, use WSL.
</Callout>

## 1. uv and git

uv manages the Python environments of your projects, and the interpreters themselves, so there is no
separate Python to install:

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

Check for git with `git --version`. On macOS, install the Xcode Command Line Tools if needed;
on Linux, use your package manager.

<Callout title="On an HPC system">
  uv installs into your home directory, so the same command works on clusters that don't provide it,
  such as NERSC's Perlmutter. Make sure `~/.local/bin` is on your `PATH`.
</Callout>

## 2. Tell git who you are

The Lightcone CLI commits every output it makes, so git needs an identity before the first run:

```bash
git config --global user.name "Ada Lovelace"
git config --global user.email "ada@example.org"
```

If you already commit from this machine, you're done.

## 3. The Lightcone CLI

The package is `lightcone-cli` on PyPI; the command it provides is `lc`. Install it with its exact
version:

```bash
uv tool install lightcone-cli==0.5.0rc5
lc --version
```

The version matters while the current release is a pre-release: without it, uv installs an older
stable release that the agent plugin doesn't support. The CLI also brings git-annex, which stores the
data and results of your projects.

<Callout title="An existing lc alias">
  If your shell already has an alias named `lc` (some people bind it to `ls --color`), it hides the
  new command. Rename the alias, or run `unalias lc`.
</Callout>

## 4. The agent plugin

Follow [Agent Skills installation](/agent-skills/installation) to add the
`LightconeResearch/agent-skills` marketplace and install the `lightcone` plugin for your agent.
It includes ASTRA support.

The plugin checks the CLI version at session start. Once both are installed, continue with
[Start an analysis](/#start-an-analysis).

## Optional extras

### Container runtime

Only projects that opt into containers need [Podman](https://podman.io/) or
[Docker](https://docs.docker.com/get-docker/). Until a project does, its recipes run directly on your
machine, in the project's own locked environment. There is nothing to configure: `lc` uses whichever
runtime it finds.

### Report preview

Each project comes with a MyST report. Previewing it needs [Node.js](https://nodejs.org/) 20 or newer
and the MyST CLI. See [MySTRA prerequisites](/mystra/getting-started#prerequisites).

### Lightcone Lab

Follow [Lightcone Lab installation](/lightcone-lab/installation) to choose a browser-only
workbench or the full installation with server features. Install it in the environment used by
your JupyterLab server.

## Updating

Install the new version by name; it replaces the one you have:

```bash
uv tool install lightcone-cli==<version>
```

`uv tool upgrade` doesn't move to a pre-release, so name the version while the release is one. The
CLI version is recorded in provenance but is not part of the output identity, so changing it alone
does not mark outputs stale. Check release notes for changes to formats and execution behavior.

## Uninstalling

```bash
uv tool uninstall lightcone-cli
```

Your projects are untouched: everything the CLI knows about an analysis lives in the project's own
repository.
