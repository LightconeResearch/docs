The stack is a set of separate tools that work on one repository: the project's own git
repository, whose `astra.yaml` describes the analysis in [ASTRA](/astra). The Lightcone CLI reads
that file to run the analysis and commits each result next to it, with a record of how it was made.
Lightcone Lab, MySTRA and the Agent Skills read the same file and the same record. They share
nothing else, so you can use, replace or leave out any of them on its own.

We split the stack up this way so that it can attach to a project that already exists. A research
group has its own code, its own compute and its own way of writing papers, and it rarely wants to
move all of that into a new system at once. With separate tools, you can start by writing the
specification with your agent and running it with the CLI, and add Lab or MySTRA later, or not at
all. The specification is plain YAML with an open schema, so a tool we didn't write, including one
you write yourself, can read it too.

The code is yours and lives wherever you put it. A recipe in `astra.yaml` names the command that
runs it, and `lc` commits what comes out next to it, in the same repository as the specification
and the data. Each layer in the figure has its own section; select one to read more.

## You and your agent

The agent does much of the work, but not the judgment:

- **It starts with questions, not code.** Before anything runs, the agent interviews you and writes
  the analysis down in the specification, where you can read it.
- **It never writes a result itself.** The agent describes the analysis and drives the CLI; every
  output comes out of `lc`, with its provenance, never out of the conversation.
- **You own the argument.** You make the scientific choices and remain responsible for what the
  results mean. The record makes those choices visible, to you and to your readers.
