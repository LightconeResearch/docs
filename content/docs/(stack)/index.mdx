The Lightcone Research Stack is [Lightcone Research](https://lightconeresearch.org)'s tooling for
research analyses described with [ASTRA](/astra) (Agentic Schema for Transparent Research Analysis).

Your AI agent can write and run an analysis faster than you can check it, yet before you publish the
result you need to know which choices went into it, and to be able to run it again when a referee
asks. The Lightcone Research Stack keeps that record for you, as an ASTRA description of the
analysis. Before writing any code, the agent works through the plan with you: you make the scientific
choices, and it records each one with the evidence behind it. Every result then comes from a recorded
run, so you or a collaborator can trace a figure back to the decisions that shaped it and reproduce
it months later.

The Lightcone Research Stack works with Claude Code and Codex, on your own code and data.

## How it works

The stack is a set of separate tools that work on one repository: the project's own git
repository, whose `astra.yaml` describes the analysis in [ASTRA](/astra). The Lightcone CLI reads
that file to run the analysis and commits each result next to it, with a record of how it was made.
[Lightcone Lab](/lightcone-lab), [MySTRA](/mystra) and the [Agent Skills](/agent-skills) read the same file and the same record. They share
nothing else, so you can use, replace or leave out any of them on its own.

We split the stack up this way so that it can attach to a project that already exists. A research
group has its own code, its own compute and its own way of writing papers, and it rarely wants to
move all of that into a new system at once. With separate tools, you can start by writing the
specification with your agent and running it with the CLI, and add [Lab](/lightcone-lab) or [MySTRA](/mystra) later, or not at
all. The specification is plain YAML with an open schema, so a tool we didn't write, including one
you write yourself, can read it too.
