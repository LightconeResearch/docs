The Agent Skills are the part of the stack that your coding agent reads. They follow the open
[Agent Skills](https://agentskills.io) format and are packaged as a plugin for Claude Code and
Codex, in the terminal or in their desktop apps.

## The lightcone plugin

The `lightcone` plugin works with you on a whole Lightcone project: it scopes the analysis with you,
runs it with `lc`, diagnoses failures, keeps the report in sync with the results, and publishes. It
has three skills:

| Skill                | What it covers                                                                 | Claude Code, Claude app, Codex app | Codex CLI                       |
| -------------------- | ------------------------------------------------------------------------------ | ---------------------------------- | ------------------------------- |
| `lightcone`          | The project, from the first interview to publication                           | `/lightcone:lightcone`             | `$lightcone:lightcone`          |
| `astra`              | The [ASTRA](/astra) format: writing, validating and restructuring `astra.yaml` | `/lightcone:astra`                 | `$lightcone:astra`              |
| `lightcone-feedback` | Reporting a bug, a feature request or a docs problem to the Lightcone team     | `/lightcone:lightcone-feedback`    | `$lightcone:lightcone-feedback` |

You rarely need to call them. Agents load a skill on their own when the task matches it: the
`lightcone` skill when you start, resume, run, debug or publish an analysis, or ask to run or fix one
in a directory that holds an `astra.yaml`; the `astra` skill when the agent reads or writes an ASTRA
file; the `lightcone-feedback` skill when you ask it to [report a problem](#report-a-problem). The
[Quick Start](/agent-skills/getting-started) installs the plugin.

## How the skills behave

- **The scientific choices stay yours.** A new analysis starts with an interview, not with code.
  Candidate decisions, findings and evidence are written to `astra.yaml`, where you can review them,
  and the conversation keeps to a summary.
- **Nothing is installed without asking.** In an interactive session the agent offers the command
  and waits for your answer. Only in a headless run, where no one can answer, does it act, and then
  it says what it changed.
- **Compute beyond your own machine needs a yes.** The agent starts a local cluster when there is
  something to run, and tells you. A remote allocation, several nodes or GPUs can spend your hours
  and queue time, so it shows you the plan first.
- **Everything runs through `lc`.** The agent never calls the container runtime, the sandbox or a
  job scheduler itself, so every output carries its run record.
- **Quotes are checked.** A quote from a paper is verified against the PDF before it enters the
  specification; one that can't be verified is dropped, not cited.

## Report a problem

When something in the stack breaks, or you want to suggest a change, tell your agent:

```text
Report this to the Lightcone team.
```

The `lightcone-feedback` skill writes a GitHub issue from what happened in the session, with
credentials and personal paths removed. It files the issue in the repository of the tool you were
using and checks for an existing report first; if it finds one, it asks whether to file anyway,
comment on it, or stop. It shows you the complete issue and files it only once you approve; ask for a
draft if you'd rather file it yourself.

Filing uses the [GitHub CLI](https://cli.github.com/), signed in with `gh auth login`. If it isn't set
up yet, your agent walks you through it first.

MySTRA, install the feedback skill on its own from the same marketplace:

## Pinned tool versions

The skills drive two command-line tools, each pinned to the version they are written against:

| Tool                                | Pin        | How it is used                                                                                             |
| ----------------------------------- | ---------- | ---------------------------------------------------------------------------------------------------------- |
| `astra-tools` (the `astra` command) | `0.2.18`   | Run as `uvx astra-tools@0.2.18`, which fetches it on first use. Never a bare `astra` found on your `PATH`. |
| `lightcone-cli` (the `lc` command)  | `0.5.0rc5` | Installed once, by you. The pin is the minimum the `lightcone` plugin accepts; newer versions are fine.    |

Each plugin update can move these pins. When the `lc` pin moves past the version you have, the
plugin notices at the start of the next session and your agent offers the install command.
