[Installation](/installation) covers the standard setup: uv and git, a git identity, the pinned
`uv tool install lightcone-cli==0.5.0rc5`, container runtimes, updating and uninstalling. This page
adds what is specific to `lc`.

## What the install brings

The published name on PyPI is `lightcone-cli`; the command it provides is `lc`. `lc` uses uv as its
environment manager: projects are `pyproject.toml` + `uv.lock`, and uv manages the Python
interpreters too, so there is no separate Python install step.

The install also puts `git-annex` on your `PATH`, alongside `lc`. Projects need it there: an
ordinary `git add` in a project runs git-annex. If `lc` runs but `git-annex` doesn't, uv's tool
directory is not on your `PATH`; run `uv tool update-shell` and open a new shell.

## Sanity check

```bash
lc --version                # → lc, version ...
lc --help
lc init --help
```

Each should print its version or help text.

<Callout title="An existing lc alias">
Run `type lc` to check whether an alias hides the command. If it does, rename the alias or remove
it with `unalias lc` before checking `lc --version`.
</Callout>

## Installing with pip

uv is the recommended installer, but `lc` also installs with pip. Keep the exact version, for the
same reason as with uv:

```bash tab="Install"
python -m pip install lightcone-cli==0.5.0rc5
```

```bash tab="Update"
python -m pip install lightcone-cli==<version>
```

```bash tab="Uninstall"
python -m pip uninstall lightcone-cli
```

pip puts `lc` and `git-annex` in that Python environment's own `bin` directory, so keep it on your
`PATH` whenever you work in a project. Avoid running `lc` through `uvx`, which puts nothing on your
`PATH` at all; see
[the clean filter failure](/lightcone-cli/troubleshooting#fatal-clean-filter-annex-failed).

## On NERSC Perlmutter

Install uv as described in [the stack setup](/installation#1-uv-and-git), and ensure
`~/.local/bin` is on your `PATH`. Two execution details matter on Perlmutter:

- **Local compute is refused on login nodes.** Use a compute node in an interactive allocation, or
  a configured Slurm offer; see [Running on a cluster](/lightcone-cli/cluster#local-allocations).
- **uv's cache must move off `$HOME`**, because Perlmutter's compute nodes cannot lock files there.
  See [Configure Slurm](/lightcone-cli/cluster#configure-slurm).

## Container runtimes

For containerized projects, install Podman or Docker as described in
[stack setup](/installation#container-runtime). Runtime detection tries `podman-hpc`, then
`podman`, then `docker`, skipping Docker if its daemon is not running. For HPC setup, see
[Running on a cluster](/lightcone-cli/cluster).
