The Lightcone CLI is an agent-native scientific workflow management system designed
to orchestrate the materialization of research artifacts declared in an `astra.yaml`
file while guaranteeing their provenance and reproducibility.

<Callout type="warn" title="Alpha development">
lightcone-cli is in **early alpha**. The CLI is still evolving: expect
breaking changes between minor versions. Bug reports, design challenges, and use cases the tooling
doesn't yet cover are exactly what we want to hear at this stage; please open an issue on the
[GitHub repo](https://github.com/LightconeResearch/lightcone-cli/issues).
</Callout>

## What it does

- **Provenance by construction.** Every output is committed to git together with a
  content-addressed manifest and a re-runnable run record; git-annex carries the bytes, so results
  travel with the repository.
- **Containers and HPC.** Declare `[tool.lightcone.image]` and recipes run in a content-addressed
  image archived in the repository itself; allocate local or Slurm Dask clusters explicitly with
  `lc compute`, then pass the cluster name or full ID to `run` or `materialize`.
- **Publication view.** Declare a license and `lc materialize` maintains an
  [RO-Crate](https://www.researchobject.org/ro-crate/) of the project and its provenance, ready to
  archive or deposit.

## In a handful of lines

With the CLI [installed](/lightcone-cli/installation), the shortest path from an empty directory to committed
results is:

```bash
# Create a new analysis
lc init my-analysis
# Describe your analysis in astra.yaml, write your scripts,
# and add their dependencies with uv
# When you are done editing, commit your changes
git add -A && git commit -m "First analysis"
# Allocate compute resources to materialize your scientific outputs
lc compute launch --wait
# Generate outputs with full provenance tracking
lc materialize local
```

The [Quick Start](/lightcone-cli/getting-started) walks through it step by step. Every output is
committed together with the code that produced it, which is why a build starts from a clean tree.
