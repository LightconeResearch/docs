Use these pages when changing the CLI or execution engine. They explain module responsibilities,
shared interfaces and the tests that check execution and provenance.

If you're looking for the user-facing docs, start from the [overview](/lightcone-cli) and
[Getting started](/lightcone-cli/getting-started).

## What this covers

- [Architecture](/lightcone-cli/architecture): the CLI/engine/ASTRA split, the run pipeline,
  identity, storage, the exec boundary, and the invariants that hold them together.
- [CLI reference](/lightcone-cli/commands): every `lc` command, with its flags, JSON report shapes
  and exit codes.
- [Engine internals](/lightcone-cli/internals): the `lightcone.engine.*` modules, with what each
  owns, its key symbols, and what must stay true of it.
- [Contributing](/lightcone-cli/contributing/setup): clone, install, run the test suite;
  [how the suite is shaped](/lightcone-cli/contributing/testing); and
  [where a change belongs](/lightcone-cli/contributing/extending).

## Start contributing

Follow [development setup](/lightcone-cli/contributing/setup) for installation and checks,
then use the [change map](/lightcone-cli/contributing/extending) to find the relevant module.

## Shared conventions

- Keep commands non-interactive and operate on the current project directory.
- Reuse the shared implementations for classification, paths, run records and tool discovery.
- Report the enforcement used, skipped checks and unavailable content explicitly.
- Document only commands and options the installed version supports.
