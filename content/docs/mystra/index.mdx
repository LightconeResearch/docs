MySTRA is a [MyST](https://mystmd.org/) plugin for writing reports about an [ASTRA](/astra)
analysis. You write the prose in Markdown and insert references to decisions, findings, figures
and measured values. MySTRA reads the analysis and its result files when MyST renders the page.

For example, if your analysis declares a fitting method, a table of fitted parameters and a plot,
your report can use them like this:

```markdown
With {astra:value}`decisions.fit_method`, the fitted slope is
{astra:value col=slope sig=3}`outputs.fit_params`.

:::{astra} outputs.fit_plot
:caption: The data and fitted relation.
:::
```

The selected method and slope come from the analysis; the figure comes from the output file.
After changing the results, rebuild the report and review whether the prose still describes them.
See [the paper preview](/astra#explore-a-paper) for an example with interactive record inspection.

## What you write, what the plugin reads

| Source | What it supplies |
| --- | --- |
| `astra.yaml`, `universes/` and `results/` | Analysis records, the selected configuration and result artifacts |
| Your Markdown pages | The argument, explanations and placement of referenced elements |
| The MyST theme | Layout and presentation, including any interactive record views |

MySTRA uses the standard MyST CLI. MyST handles the build, citations, cross-references and asset
copying. A theme can add dialogs for inspecting ASTRA records; the references also render with
ordinary MyST themes.

## Set up a report

Projects created with `lc init` already contain `myst.yml` and an `index.md` report. For those
projects, install the MyST CLI and start [writing references](/mystra/getting-started#write-your-first-references).
For other ASTRA projects, [Getting started](/mystra/getting-started) covers plugin registration too.

MySTRA is pre-1.0. Pin a release in `myst.yml` for reports you need to rebuild later.
