Start with an ASTRA project and some result files. This guide sets up MyST, adds references to the
analysis, and builds a report.

If you'd rather see the authoring vocabulary first, jump to the
[authoring guide](/mystra/authoring).

<Callout title="Projects created with lc init">
Your project already has a `myst.yml` that registers the plugin, and an `index.md` report. Install
the MyST CLI (see [Prerequisites](#prerequisites)), then go straight to
[Write your first references](#write-your-first-references).
</Callout>

## Prerequisites

MySTRA renders reports *on top of* an ASTRA analysis, so you need:

1. **An ASTRA project** — a directory with an `astra.yaml`, optionally one or more universe files in
   `universes/`, and (for figures/tables/values) materialised results in `results/`. Without a
   universe file, the SDK uses the decisions' authored defaults. New to ASTRA? Start with the
   [ASTRA getting-started guide](https://astra-spec.org/latest/getting-started/) first, or read
   [ASTRA](/astra) for how the Lightcone Stack uses it.
2. **The MyST CLI** (`mystmd`), which needs Node ≥ 20:

   ```bash tab="npm"
   npm install -g mystmd
   ```

   ```bash tab="pip / uv"
   uv tool install mystmd     # or: pip install mystmd
   ```

   Verify with `myst --version`.

There is nothing to install for MySTRA itself: MyST loads a plugin from a single bundled `.mjs` file
referenced by URL.

## Register the plugin

In your ASTRA project directory, create a `myst.yml` that points at the pinned release artifact and
lists your pages:

```yaml title="myst.yml"
version: 1
project:
  plugins:
    - https://github.com/LightconeResearch/MySTRA/releases/download/v0.0.1/mystra.mjs
  toc:
    - file: index.md
site:
  template: book-theme
```

MyST downloads and caches the plugin on the first build. The example pins `v0.0.1`;
check [MySTRA releases](https://github.com/LightconeResearch/MySTRA/releases) when choosing a
version. Projects created with `lc init` currently use a `latest` URL, which you can replace
with a tagged release before publication.

## Project layout

MySTRA expects the standard ASTRA conventions:

```text
my-analysis/
├── astra.yaml          Analysis specification (decisions, findings, outputs, …)
├── universes/
│   └── baseline.yaml   Decision selections for the baseline universe
├── results/
│   └── baseline/<output-id>.png               Materialised result artifacts
├── myst.yml            Registers the plugin; lists pages
└── index.md            Your report (+ optional sub-analysis pages)
```

## Write your first references

Create an `index.md` using [paths](/mystra/authoring/paths) to the records in your analysis.
This example assumes a `fit_method` decision and a `fit_params` table output with a `slope`
column. Substitute your own IDs and column names:

```markdown title="index.md"
# My analysis report

With {astra:value}`decisions.fit_method`, we find
{astra:value col=slope sig=3}`outputs.fit_params`
for the slope of the relation.

:::{astra} outputs.fit_params
:::

:::{astra} decisions.fit_method
:::
```

The example uses two kinds of reference:

- the **`{astra}` directive** embeds a record as a block — [block embeds](/mystra/authoring/block-embeds);
- the **`{astra:value}` role** reads a measured value or selected option — [live values](/mystra/authoring/live-values).

Everything else — prose, math, figures you author yourself, the table of contents, multi-page
structure — is ordinary MyST.

## Preview

Run the stock MyST CLI from the project directory:

```bash
myst start        # → http://localhost:3000
```

MySTRA reads `astra.yaml` from the working directory and uses the ASTRA SDK to validate and
resolve the project. With multiple universe files, the SDK selects the first `.yaml` or `.yml` filename in lexical order; with
none, it uses authored defaults.

<Callout title="Editing astra.yaml while the server runs">
`myst start` watches your Markdown files, not the ASTRA spec. Whenever MyST does render a page, the
plugin compares every file, directory listing, missing artifact, and metadata entry the SDK read
before reusing its resolved bundle. A re-render is still triggered by a Markdown change, so after
editing `astra.yaml`, re-save any `.md` page (or restart the server) to see the update.
</Callout>

## Build for publication

```bash
myst build --html
```

This produces a static site in `_build/html/`. Inspect the build diagnostics and preview the
report before sharing it: unresolved references can still produce a page with fallback text or
an error message. MyST copies referenced result assets into the build; externally hosted content
still needs its original host.
